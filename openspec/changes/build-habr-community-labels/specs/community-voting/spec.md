## Purpose

Позволяет читателям публично оценивать происхождение текста статьи и понимать, какие голоса сформировали её метку.

## ADDED Requirements

### Requirement: One current vote per article and user
Система SHALL хранить не более одного текущего голоса пользователя на ID статьи Хабра с оценкой human, partial или ai и необязательным текстовым комментарием до 2000 символов. Пользователь SHALL иметь возможность заменить или удалить собственный голос. Варианты URL одной статьи SHALL использовать общие голоса.

#### Scenario: Create and replace
- **WHEN** пользователь голосует human без комментария, затем меняет голос на partial с комментарием
- **THEN** существует один голос partial с последним комментарием и обновлённой датой изменения

#### Scenario: Delete and retry
- **WHEN** пользователь удаляет свой голос и повторяет удаление
- **THEN** голос отсутствует, повтор не создаёт ошибку и агрегат не содержит удалённый голос

#### Scenario: Concurrent requests
- **WHEN** один пользователь одновременно отправляет несколько голосов для одной статьи
- **THEN** сохраняется не более одного голоса и итоговый агрегат соответствует сохранённым данным

#### Scenario: Invalid input
- **WHEN** отправлены неизвестная оценка, невалидный ID статьи или комментарий длиннее лимита
- **THEN** запрос отклоняется без изменения данных

### Requirement: Deterministic community label
Система SHALL вычислять N = human + partial + ai по действующим голосам: при N=0 — grey; при human=N>0 — green; при ai>=3 и 5*ai>=4*N — red; иначе yellow. partial SHALL входить в знаменатель и не входить в число ai. Метка SHALL описываться как мнение сообщества, а не доказательство происхождения или качества текста.

#### Scenario: Classification boundaries
- **WHEN** запрашиваются агрегаты со следующими количествами human/partial/ai
- **THEN** результат соответствует таблице без округления процентов

| human | partial | ai | label |
|---|---|---|---|
| 0 | 0 | 0 | grey |
| 1 | 0 | 0 | green |
| 0 | 1 | 0 | yellow |
| 0 | 0 | 2 | yellow |
| 0 | 0 | 3 | red |
| 1 | 0 | 3 | yellow |
| 1 | 0 | 4 | red |
| 0 | 1 | 4 | red |
| 0 | 2 | 4 | yellow |

#### Scenario: Mutation updates classification
- **WHEN** один из трёх ai-голосов удаляется
- **THEN** результат становится yellow с двумя ai-голосами

### Requirement: Public vote visibility
Система SHALL предоставлять без авторизации агрегаты и постраничный список действующих голосов: публичное имя GitHub, ссылка на профиль, оценка, комментарий при наличии и время изменения. Список SHALL иметь стабильный порядок от недавно изменённых к старым при неизменных данных. Сессии, email и токены SHALL оставаться приватными.

#### Scenario: Anonymous inspection
- **WHEN** неавторизованный читатель открывает список голосов и загружает следующую страницу
- **THEN** он видит публичные поля без требования входа и без повторов при неизменных данных

#### Scenario: Unknown article
- **WHEN** запрашивается корректный ID статьи без голосов
- **THEN** возвращаются нулевые количества, grey и пустой список

### Requirement: Abuse controls and safe comments
Система SHALL выводить комментарии как текст, ограничивать частоту записей и предоставлять защищённый операторский способ скрыть комментарий и заблокировать злоупотребляющий аккаунт. Скрытие комментария SHALL сохранять голос; блокировка SHALL запрещать записи, отзывать сессии и исключать голоса аккаунта из публичных результатов. Эти правила SHALL одинаково применяться к спискам и агрегатам.

#### Scenario: Unsafe comment
- **WHEN** комментарий содержит HTML или JavaScript
- **THEN** содержимое отображается как текст и не выполняется

#### Scenario: Rate limit
- **WHEN** пользователь превышает настроенный лимит записи
- **THEN** API отвечает 429 с временем повторной попытки и не меняет голос

#### Scenario: Moderation
- **WHEN** оператор скрывает комментарий, затем блокирует его автора
- **THEN** сначала скрывается только комментарий, а после блокировки голос исключается и метка пересчитывается; обычный пользователь не может выполнить эти операции
